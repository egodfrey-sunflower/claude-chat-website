Zarr, visually

Zarr stores big N-dimensional arrays as a pile of small, separately compressed chunks in any key/value store: a folder, S3, a zip file. It has no container format. The whole thing is JSON metadata plus a naming rule for chunk keys. Tap through the demos below. The bytes are computed live and follow the Zarr v3 spec.

1The big picture

2Chunk grid explorer

Pick an array shape and a chunk shape, then tap any element. You'll see which chunk holds it, which key that chunk is stored under, and where the element sits inside the chunk. Hatched cells are padding: edge chunks are always stored at full size, even where they overhang the array.

3Writing data: what lands in the store

Drag across the array to write values. A chunk only exists in the store once it holds something other than fill_value (0 here). Faded chunks have no key, and reading them just returns zeros. Erase a chunk back to all zeros and zarr-python deletes its key by default.

Keys in the store

    It's a flat key/value store. On a filesystem, each / in a key becomes a directory.

    4The codec pipeline: one chunk, from array to stored bytes
    
    
    Every chunk passes through the array's codecs list, in order: any array → array codecs, then exactly one array → bytes codec, then any bytes → bytes codecs. Reading runs the same list backwards. Colours follow each value's original row, so you can watch the bytes get reordered.

    6Sharding: many chunks in one object
    
    
    Lots of tiny chunks means lots of tiny objects, which is slow and expensive on cloud storage. The sharding_indexed codec packs a grid of inner chunks into one stored object (a shard), with an index of (offset, nbytes) pairs at the end. This array is 8 × 8 uint8, with shards of 4 × 8 and inner chunks of 2 × 4. Tap inner chunks to write or erase them, and watch the shard's bytes change.

      7v2 vs v3 at a glance
      
    
      
      
      Zarr v2Zarr v3
      
      
      Metadata.zarray, .zgroup, .zattrsone zarr.json per node, attributes inline
      
      
      Chunk key0.0 (or 0/0)c/0/0 (or c.0.0)
      
      
      dtypeNumPy typestr like <i2, byte order built inint16; byte order is a bytes codec setting
      
      
      Encodingfilters + one compressor, plus order C/Fa general codecs chain (with transpose instead of order)
      
      
      Shardingnosharding_indexed codec
      
      
      Extensionsad hocnamed extension points, with must_understand
